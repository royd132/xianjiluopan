# 评审问答与提交检查表

## 常见追问

### 为什么一定要多 Agent？

不同任务具有不同的输入、验证方式和失败模式：原语评论需要语义模型，价格与趋势需要确定性统计，供应链需要阈值监控，最终建议需要 Schema 编译与安全校验。将它们拆为专业 Agent，可以并行执行、独立评测、单点降级，并通过黑板追踪每个结论的来源。

### 这是不是只有多 Agent 的概念图？

不是。仓库已经包含六类 Agent、CollaborationBlackboard、事件协议、阶段并行 Runtime、Trace、SQLite Memory、Checkpoint、四卡评测闸门、FastAPI/SSE、CLI 和自动化测试。默认离线模式可以直接生成完整报告。

### Harness 有什么实际作用？

Harness 位于 Agent 外层，统一记录开始、完成和异常，限制工具，保存 Checkpoint 和任务组件快照，并写入长期记忆。扩展平面按 global/workspace/market/task 解析 Provider，通过 Effect Stack 撤销失败安装。它解决的是 Agent 能否被恢复、审计、评测和安全替换的问题，而不是增加一个新的聊天角色。

### Mock 数据是不是造假？

Mock 模式在页面、API 和报告中明确标记，目的在于让评审无网络、无密钥也能复现完整系统。当前实现不是单一固定脚本，而是由品类画像与市场画像共同生成评论痛点、价格、竞品空位、渠道和供应链信号；Mock 证据的 `verified` 字段为 `false`。真实接入不会改变 Agent 工作流，项目不会把 Mock 结果描述为真实实时发现。

### 现在真的在持续监控市场吗？

还没有。当前已实现的是按需研究任务、SSE 任务事件、反向条件登记和可恢复执行；定时市场快照、变化检测与阈值告警属于下一阶段。页面明确显示“待接入”，避免把 Runtime 实时进度误称为市场实时监控。

### 商家为什么愿意付费？

产品切入的是付样品费、开模、首批备货和广告投放前的决策时刻。它不替商家自动采购，而是减少错误项目进入库存的概率，并把调研时间、证据核查和种子验证固化成团队流程。商业化可采用单次研究任务包、团队订阅和真实数据接入后的持续监控订阅。

### 如何控制模型幻觉？

模型不负责精确数值计算。Decision Compiler 只能读取结构化事实；Safety Evaluator 强制检查证据数量、非英语来源、私域钩子和失效条件。缺少必填字段时不发布最终卡片。

### 自进化是否已经实现？

已实现反馈收集、正负案例、失败类型、版本化策略候选、完整 DecisionCard Validation/Holdout 回放、人工激活和父版本回滚。这属于策略级 Layer 3a；SFT、LoRA 与 Agentic RL 仍是积累足够合规反馈后的后续路线。

### DSH 的热插拔是否真正落地？

是。Provider 安装经过 staging、健康检查和激活，注册副作用进入逆序清理栈；同名工具按作用域遮蔽，Capability Guard 的拒绝不可被局部插件绕过。每个任务固定组件快照，所以热更新只影响新任务，旧任务和恢复任务继续使用原 generation。系统没有照搬“everything is a plugin”，核心状态机、Run Ledger 和任意代码执行不参与热替换。

### 与传统选品工具的差异？

传统工具偏重指标和榜单；先机罗盘输出可执行四卡，并提供原语痛点、私域落点、证据链、反向条件、运行审计和人工反馈闭环。它也可以把传统数据工具作为上游数据源，而不是简单替代它们。
