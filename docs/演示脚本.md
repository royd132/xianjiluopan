# 先机罗盘 · 复赛演示脚本

> 目标时长：4 分 30 秒。前 60 秒全部讲商家问题。
> 主案例：宠物自动喂食器 × 巴西（Real 模式）；泛化验证：咖啡磨 × 美国（Hybrid 模式）。

## 0:00–1:00 商家问题与四张卡（业务先行）

打开工作台，输入"宠物自动喂食器"和"巴西"，点击开始。

> 中小卖家准备付样品费、开模、下首批订单时，面对的是趋势、评论、竞品价格、海关、汇率、物流六类分散数据，和"我感觉能卖"的经验判断。传统工具给数据看板，通用 AI 给文字建议，但最后 Go / Validate / Stop 仍靠人拼。先机罗盘把多源证据编译成四张卡：选品方向、定价策略、竞争打法、最小市场验证——每张卡都有证据链、有效期、失效条件和人工复核状态。

展示 6 个 Agent 的 SSE 实时进度，33 秒后四卡出现。

> 不是预录动画，是 FastAPI SSE 推送的真实 Runtime 事件。

## 1:00–1:50 选品卡与多语言痛点

点击选品卡详情。展示证据链和原语评论。

> 这张卡建议优先验证"低噪音定时喂食"。8 条证据中包含 3 条巴西葡语原语评论——系统保留原文"Gostei, mas faz muito barulho a noite"（我喜欢，但夜间太吵），Qwen 模型只返回源 review ID，代码取回原文，避免翻译丢失隐性痛点。这种"喜欢但有缺陷"的结构比纯差评更适合发现差异化机会。

指出失效条件。

> 卡片底部写着"Top 10 中公开噪音测试的竞品 >= 4 个时重新评估"。系统不仅告诉卖家为什么建议成立，也说明什么时候结论会失效。

## 1:50–2:30 定价卡与供应链信号

点击定价卡。展示供应链信号面板。

> 定价卡以 Amazon 商品快照中位数为锚点给出测试区间，并标注物流成本超过 15% 时重新计算。供应链面板实时展示汇率、贸易和运价信号，当信号越过阈值时触发重新计算。

## 2:30–3:10 百炼模型 Grounding 与证据门禁

展示代码或 Trace 中 Qwen 调用记录。

> 系统调用阿里云百炼 Qwen 3.7 Flash 模型分析多语言评论。关键是 Grounding 机制：模型被约束为只返回源评论 ID 和痛点分类，代码再根据 ID 取回原文。模型不能编造不存在的评论。每次调用记录 prompt 指纹和模型版本。

打开安全评测闸门说明。

> Safety Evaluator 是线上线下共享的硬门禁：证据数不足、无非英语来源、缺少失效条件时直接拒绝发布卡片。数据不足不输出，不会静默降级成好看但无依据的建议。

## 3:10–3:45 人工复核与经验复用

点击驳回一张卡。展示演进中心。

> 人工驳回不是装饰。反馈进入 SQLite 长期记忆，系统自动提取检查模式存入 Skill Bank，经回放评测后注入后续同类任务。卖家驳回过的问题，下次自动进入规则。策略演进需要 Validation/Holdout 双分区回放通过，再加人工激活才能上线，不会被单次反馈直接改写。

## 3:45–4:15 跨场景泛化

切换为"coffee grinder × US"，展示结果变为美国市场。

> 同一个系统，切换到美国咖啡磨后，痛点变为低残粉和刻度复现，数据源变为 Amazon US 和北美运价，种子渠道变为 Reddit。不是替换品类名称的固定脚本。当前已有 BR 宠物喂食器（Real）、US 咖啡磨（Hybrid）、MX 榨汁机（Mock）、US 降噪耳机（Mock）四份跨品类报告。

## 4:15–4:30 总结

> 先机罗盘在卖家第一次不可逆投入前，把分散的市场证据编译成可追溯、可过期、可推翻的 Go / Validate / Stop 决策。Docker 一键启动，离线模式无需 API Key 即可完整演示。
