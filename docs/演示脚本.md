# 先机罗盘完整 Demo 脚本

> 建议时长：5–6 分钟。主案例：宠物自动喂食器 × 巴西；泛化验证：便携咖啡磨 × 美国。

## 0:00–0:40 业务问题

展示工作台并输入品类与市场。

> 真正高风险的不是看报告，而是卖家准备付样品费、开模、下首批订单和投入广告的那一刻。传统工具给很多数据，但最后仍要靠人把它们拼成决定。先机罗盘把“我感觉能卖”变成“哪些证据支持、先验证什么、什么情况下停止”。

## 0:40–1:20 多 Agent Runtime

点击“开始洞察”，展示实时进度。

> 任务进入 CollaborationBlackboard。Collector 先发布原始数据；原语评论、市场和供应链 Agent 并行分析；Decision Compiler 编译四卡；Safety Evaluator 最后执行硬闸门。前端看到的不是预录动画，而是 FastAPI SSE 发送的 Runtime 事件。

可以补充展示 `/docs` 或 Trace 文件，证明事件、Agent 和 Checkpoint 真实存在。

## 1:20–2:10 四张决策卡

展示选品、定价、竞争和最小市场验证四张卡。

> 选品卡给出差异规格；定价卡给出价值锚和物流阈值；竞争卡要求把卖点变成可验证证据；最小市场验证卡进一步回答先找谁、在哪里验证、验证什么、需要多少样本、什么情况下停止。卖家可以先完成 30 份意向测试和 5 次深访，再决定首批备货。

## 2:10–2:55 多语言隐性痛点

点击夜间噪音气泡并展示葡萄牙语原文。

> Review Agent 直接处理原语中的让步结构。“我喜欢，但是夜间太吵”同时证明总体需求成立和局部缺陷存在，比只统计差评更适合发现差异化机会。原文始终保留供人工核查。

## 2:55–3:45 证据与反向条件

打开选品卡详情。

> 每张卡必须通过安全闸门：至少三条证据、至少一条非英语来源、可执行验证动作和可观测的失效条件。我们不仅告诉用户为什么建议成立，也告诉用户什么时候系统会承认自己错了。

同时指出页面状态：当前原型已经登记失效阈值，但真实数据定时快照和告警触发器仍在路线图中，不把任务 SSE 描述成市场实时监控。

## 3:45–4:30 Harness

展示 `.foresight/traces.jsonl`、Checkpoint 或架构图。

> Harness 统一管理 Agent 的 Trace、Memory、Checkpoint 和工具安全。对商家来说，它保证一条可能影响采购的建议可以恢复、审计和复现；Provider 热更新后，旧任务仍锁定原来的数据与策略版本。

## 4:30–5:10 人工复核与自进化

点击采纳或驳回。

> 人工复核不是装饰。反馈会进入 SQLite 长期记忆，被沉淀为正向或负向案例。当前仓库已经实现反馈飞轮的前两层；等积累足够合规样本后，才进入 SFT、LoRA 或强化学习阶段。

## 5:10–5:40 离线可复现

展示 CLI 生成的 `reports/demo.json` 和测试结果。

> 为了让评审稳定复现，项目默认不依赖 API Key。场景化 Mock 由“品类画像 × 市场画像”生成一致的痛点、价格、渠道和供应链信号，也完整经过同一套 Agent、Harness、闸门和反馈流程。所有 Mock 证据明确标记为非真实核实结果。

把输入切换为 `portable coffee grinder × US`，展示结果已经同步变为美国市场、低残粉与刻度复现、Amazon US、北美运价和 Reddit/邮件种子渠道，证明不是替换品类名称的固定巴西脚本。

## 5:40–6:00 总结

> 先机罗盘在第一次不可逆投入前，帮助卖家完成一次有证据的 `Go / Validate / Stop` 判断。多 Agent 负责专业分工，Harness 负责可信执行，反向条件负责让系统知道什么时候应该重新判断。
