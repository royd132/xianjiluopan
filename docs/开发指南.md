# 开发与扩展指南

## 1. 环境

- Python 3.11+
- Node.js 20+
- Windows PowerShell、macOS 或 Linux shell

## 2. Python 开发安装

标准开发环境可以执行：

```bash
python -m pip install -e ".[dev]"
```

不安装包时，在仓库根目录设置 `PYTHONPATH=backend` 后也可运行。

## 3. 运行测试

Windows 环境若默认 Temp 目录不可写，可将 `TEMP` 和 `TMP` 指向仓库内 `.tmp`。README 已提供完整命令。

```bash
python -m pytest
npm run test:frontend
npm run build
```

## 4. 接入真实数据 Connector

汇率、贸易、供应链指数等来源实现 `backend/foresight/providers/protocols.py` 中的最小生命周期合同，并在自己的 Connector 内完成：

- 缓存文件可用性检查；
- 来源字段与数值校验；
- 市场代码和时间范围解析；
- 标准化 Snapshot 输出；
- 用 `ConnectorDataError` 披露缺失或无效数据。

`RealDataProvider` 负责组合 Connector、评论抽取和 Evidence 编译，不再直接实现每个宏观来源的 CSV 解析。新 Connector 必须增加独立合同测试。

## 5. 接入聚合 Provider

实现与 `MockDataProvider.collect()` 相同的异步接口，返回：

```python
{
    "evidences": list[EvidenceItem],
    "reviews": list[dict],
    "prices": list[float],
    "trade": dict,
    "freight": dict,
}
```

每项 Evidence 必须包含来源、类型、主张、原始值、语言、采集时间和可信度。

## 6. 接入真实模型

优先在语义任务内部增加 Model Adapter，不要让模型接管数值计算。建议能力边界：

- Review Agent：多语言痛点和引用范围抽取；
- Decision Compiler：基于结构化事实生成 Pydantic/JSON Schema；
- Safety Evaluator：可增加二次模型核对，但规则校验仍为硬闸门。

模型失败时应降级到规则或 Mock 结果，并在结果中披露。

## 7. API 装配

`foresight.api:create_app()` 接受显式 `ForesightRuntime`，路由从 `app.state` 解析依赖。测试、嵌入式部署和未来 workspace 隔离不应 monkeypatch 模块级单例。

## 8. 扩展持久化

当前 SQLite Memory 适合单机 Demo。生产演进可以：

- SQLite → PostgreSQL；
- 本地 Checkpoint → 对象存储；
- 内存事件订阅 → Redis Streams/Kafka；
- Chroma → Qdrant/Milvus。

领域模型和 Agent Artifact 不应因基础设施替换而改变。

## 9. 提交规范

- 新 Agent 必须增加测试；
- 不提交密钥和用户数据；
- 修改 Schema 时同步更新 API 和文档；
- Mock 数据必须确定性且明确标记；
- 不将规划中能力写成已经实现。
