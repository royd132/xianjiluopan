## 二、方案概述

### 1. 一句话定位

先机罗盘面向缺少海外研究团队的中小跨境卖家，在样品、开模和首批备货前，将原语评论、竞品价格、贸易、汇率与物流信号编译为可追溯、可过期、可推翻的 `Go / Validate / Stop` 决策，让卖家从“凭感觉备货”转向“基于证据先验证、再投入”。

### 2. 具体业务问题

跨境卖家并不缺数据，真正缺的是在不可逆投入之前完成一次可靠的立项判断。卖家需要同时查看竞品价格、当地语言评论、贸易需求、汇率和供应链变化，但现有榜单、数据平台和通用大模型通常存在五个断点：

1. 数据分散在多个平台，研究周期长，难以形成统一结论；
2. AI 能生成建议，却不能稳定回指原始评论和数值来源；
3. 历史快照、跨市场评论和目标市场数据容易被混成“实时事实”；
4. 报告说明“发生了什么”，却没有回答具体做什么、先验证什么；
5. 市场变化后旧结论继续流通，缺少有效期、反向条件和重算机制。

因此，本方案聚焦一个明确决策：

> **一个新品是否值得进入某个海外市场，以及在备货前应该先验证什么？**

### 3. 目标用户

- **核心用户**：1-5 人、没有海外本地研究团队、准备把成熟供应链带入陌生市场的中小跨境卖家。

工厂型卖家、代运营和出海服务商属于后续扩展客户，不作为初赛主叙事的核心用户。

### 4. 五项核心功能

#### 功能一：新品进入诊断

用户输入品类和目标市场，系统围绕首批投入给出 `Go / Validate / Stop` 结论，并展示支持证据、证据冲突和仍需补齐的信息。真实数据覆盖不足时明确降级为待验证任务，不输出伪确定性结论。

#### 功能二：原语隐性痛点雷达

AI 直接分析英语、葡萄牙语等原语评论，识别“我喜欢，但是……”一类兼具需求成立与局部缺陷的信息。模型只返回支持结论的 review ID，原文由代码取回，避免翻译损失和伪引用。

#### 功能三：选品、定价与竞争处方

系统把多源研究结果编译为三张经营处方：

- 选品方向：应该优先验证什么产品差异；
- 定价策略：价格依据、测试区间和成本补齐项；
- 竞争打法：应该审计或攻击哪个表达空位；

每张卡包含证据、置信度、有效期、失败条件和人工复核状态。

#### 功能四：最小市场验证卡

在首批备货前生成可执行的验证计划，明确先找谁、在哪里验证、验证什么假设、需要多少样本以及什么情况下停止。建议先完成 30 份意向测试和 5 次深访，再决定是否扩大投入。

#### 功能五：决策有效期监控

系统分别记录数据发生时间和系统读取时间，并把证据标记为近期、历史基线或结构性基线，同时区分目标市场、类目代理、跨市场产品证据和全球宏观信号。后续接入授权 API 后，可按数据源使用 WebSocket、Webhook 或增量轮询：

- 汇率秒级至分钟级；
- 竞品价格和库存 5-30 分钟级；
- 评论与评分 15-60 分钟级；
- 物流小时至日级；
- 海关数据按官方发布周期更新。

当汇率、物流成本、竞品价格或痛点占比越过阈值时，只重算受影响的决策卡，而不是反复运行全部 Agent。当前原型已经实现手动市场快照、观察日期、阈值和触发计数。

### 5. 方案亮点

1. **原语证据 Grounding**：模型只提交源记录 ID，原文与数值由代码取回，降低翻译损失和伪引用风险；
2. **可证伪决策处方**：不止解释市场发生了什么，还说明下一步做什么、证据何时过期、什么条件会推翻结论；
3. **变化触发局部重算**：为每类数据定义新鲜度合同，信号越过阈值后只重算受影响的卡片。

多 Agent、Harness、Provider 热更新和受控演进不是独立卖点，而是保证以上三项创新可恢复、可审计、可复现和可回滚的技术底座。真实数据不足时，系统生成补数与人工审计任务，不用 Mock 数值冒充事实。

### 6. 预期效果

以下为首轮商家试点目标，不是已实现的经营结果：

| 指标 | 传统方式 | 首轮目标 |
|---|---:|---:|
| 单品类 × 单市场端到端研究 | 2-3 个工作日 | 数据就绪后 60-90 秒生成首版；含数据确认与人工复核控制在 2 小时内 |
| 核心建议可追溯率 | 依赖人工整理 | 100% 关联证据对象 |
| 备货前验证 | 经常直接投入 | 80% 试点任务完成最小验证；建议基线为 30 份意向测试与 5 次深访 |
| 结论更新 | 人工重新检查 | 阈值触发受影响卡片重算 |
| 失效结论处置 | 依赖人工记忆 | 100% 过期卡片进入重算或人工复核队列 |

以上均为首轮试点目标，不是已经取得的经营结果。计划招募 10 位中小卖家，覆盖 3 个品类和 3 个市场，对比研究耗时、卡片采纳率、证据覆盖率、最小验证完成率和停止证据不足项目数。

## 三、技术方案

### 1. AI 能力如何落地

| 能力 | 落地方式 | 业务作用 |
|---|---|---|
| 多语言语义理解 | Qwen Model Adapter，结构化 JSON 输出 | 聚类原语评论中的隐性痛点 |
| Grounding | 模型返回 review ID，代码取回原文 | 防止伪引用并支持人工核查 |
| 多 Agent 协作 | Collector、Review、Market、Supply Chain、Decision、Safety | 将复杂研究拆成专业角色 |
| 决策编译 | Pydantic Schema + LLM/规则 | 把分析结果转成四类行动卡 |
| 确定性计算 | Python 规则和统计 | 处理价格区间、变化率和阈值 |
| 受控演进 | 反馈案例、双分区回放、人工激活 | 在不破坏线上稳定性的前提下迭代策略 |

模型负责语义理解和策略表达，统计、阈值、证据验证、时间判断和权限控制由确定性代码完成。

### 2. Agent 工作流

1. 用户提交“品类 × 国家 × 数据模式”；
2. Capability Matrix 检查数据与模型是否满足当前场景；
3. Collector 读取价格、评论、贸易、汇率和供应链数据；
4. Review、Market、Supply Chain Agent 并行分析并向共享黑板发布 Artifact；
5. Decision Compiler 生成选品、定价、竞争和最小市场验证四类卡片草稿；
6. Safety Evaluator 检查证据数、近期证据、原语来源、失败条件与 AI 标记；
7. Harness 保存 Trace、Checkpoint 和组件快照；
8. 前端通过 SSE 展示任务进度，用户完成复核；
9. 市场信号越过阈值后，触发受影响卡片重算。

### 3. 数据处理方式

- 数据接入：公开数据集、平台授权 API、Webhook、WebSocket 或增量轮询；
- 标准化：统一为 Evidence、PainPoint、SupplySignal 和 DecisionCard Schema；
- 时间治理：记录 `observed_at`、`collected_at`、观察区间、新鲜度等级和过期时间；
- 适用范围：区分目标市场、跨市场、类目代理和宏观证据；
- 质量控制：源记录 ID、去重、幂等、超时、重试、熔断和数据断流告警；
- 存储：SQLite 用于本地演示，生产环境升级 PostgreSQL、对象存储与消息队列；
- 可审计：每次任务保留数据来源、Prompt 指纹、Agent 事件和组件版本。

### 4. 技术组件

| 层级 | 组件 |
|---|---|
| 前端 | React 19、Vite、Lucide Icons |
| API | FastAPI、REST、SSE |
| Runtime | 事件驱动多 Agent、CollaborationBlackboard |

## 六、300 字摘要

先机罗盘是面向中小跨境卖家的新品首单前证据决策系统。卖家输入品类与目标国家，系统将商品价格、原语评论、贸易、汇率和供应链信号编译为 `Go / Validate / Stop` 判断，以及选品、定价、竞争和最小市场验证四类卡片。模型只返回支持结论的源记录 ID，原文与数值由代码取回；每张卡记录证据时间、市场范围、有效期和反向条件，市场变化后可触发局部重算。多 Agent 负责专业分析，Harness 负责 Trace、Checkpoint、工具权限、组件快照和回滚。当前原型已跑通巴西宠物自动喂食器真实链路，缺少当前竞品授权数据时会生成补数任务，不伪造实时事实。
